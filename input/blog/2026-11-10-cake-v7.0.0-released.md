Version **7.0.0** of Cake has been released. Take it for a spin and give us feedback on our [discussion board](https://github.com/cake-build/cake/discussions/xxxx).

This release includes new features, improvements and bug fixes to [Cake Scripting](/docs/running-builds/runners/dotnet-tool), [Cake Frosting](/docs/running-builds/runners/cake-frosting) and [Cake Sdk](/docs/running-builds/runners/cake-sdk) since the [Cake v6.3.0 release](/blog/2026/09/cake-v6.3.0-released)! 🚀 🍰

### Highlights of this release

- **.NET 11 & C# 15 support** — Cake now runs on .NET 11 and .NET 10 with C# 15 scripting support; .NET 8 and .NET 9 are no longer supported for running Cake itself.
- **One container, one host** — Cake.Tool has moved from Autofac to Microsoft.Extensions.DependencyInjection, and the `ServiceProvider` alias gives you the same DI experience across Cake .NET Tool, Cake Frosting and Cake.Sdk.
- **Unified dependency graph by default** — When running multiple targets, shared dependencies now only execute once.
- **Tools on demand** — New `InstallTool` / `InstallTools` aliases let you install tools from within a task, only when they're actually needed.
- **DSL improvements** — `IsDependentOn` / `IsDependeeOf` with multiple tasks, async `DoesForEach` (including `IAsyncEnumerable`), `IFile` content extensions aligned with `System.IO.File`, and `GetFileSystemInfos`.
- **New aliases** — `Tar` / `Untar`, `DotNetRunCode`, `DotNetUpdatePackage`, `DotNetSlnMigrate`, `DotNetProjectConvert`, `DotNetDownloadPackage`, `DotNetNuGetWhy` and `DotNetNuGetLocals`, plus new .NET 11 settings for `DotNetRun`, `DotNetTest` and `DotNetFormat`.
- **Container publishing** — `DotNetPublish` can now produce container images, pushed to a registry, loaded into a local Docker / Podman / WSL container engine, or saved as a tarball.
- **.NET 11 process APIs** — Kill child processes when Cake exits, fire-and-forget processes, discard output, and pipe content to standard input.
- **GitHub Actions to Azure without secrets** — The new `AzureLogin` command exchanges a GitHub Actions OIDC token for an Azure access token.
- **Cake.Template `cakeci` template** — Scaffold a minimal CI pipeline running your Cake file-based build for eight different CI providers.
- **Addin recommended Cake version set to 7.0.0**
- Bug fixes, dependency and SDK updates

### .NET 11 support & C# 15 support

Cake now fully supports running on .NET 11, and with this C# 15, which means you can take advantage of the latest framework, runtime, and language improvements ([#4998](https://github.com/cake-build/cake/issues/4998), [#4999](https://github.com/cake-build/cake/issues/4999)). When running on .NET 11, Cake is also built with the new .NET 11 runtime async enabled ([#5177](https://github.com/cake-build/cake/issues/5177)).

Cake itself will no longer run on .NET 8 or .NET 9 ([#4997](https://github.com/cake-build/cake/issues/4997)), but Cake will continue to support building projects targeting .NET 9, .NET 8, older versions of .NET and .NET Framework.

The supported platform matrix for Cake 7.0.0 will look like this:

| Runner                           | .NET 11                                               | .NET 10                                               |
| -------------------------------- |:-----------------------------------------------------:|:-----------------------------------------------------:|
| [Cake .NET Tool]                 | <i class="fa-solid fa-check" style="color:green"></i> | <i class="fa-solid fa-check" style="color:green"></i> |
| [Cake Frosting]                  | <i class="fa-solid fa-check" style="color:green"></i> | <i class="fa-solid fa-check" style="color:green"></i> |
| [Cake.Sdk]                       | <i class="fa-solid fa-check" style="color:green"></i> | <i class="fa-solid fa-check" style="color:green"></i> |

Cake.Template now defaults to `net11.0`.

### Breaking changes

As with every major release, we've taken the opportunity to clean things up. Most builds should just work, but these are the changes worth knowing about:

- **.NET 8 & .NET 9 dropped** — Cake now targets `net10.0` and `net11.0` ([#4997](https://github.com/cake-build/cake/issues/4997), [generator#206](https://github.com/cake-build/generator/issues/206)).
- **Unified dependency graph is now the default** — See [below](#unified-dependency-graph-by-default) for details and how to opt out ([#5060](https://github.com/cake-build/cake/issues/5060)).
- **Tri-state DotNet switches** — Switches where the .NET CLI picks a default based on the environment are now `bool?`, so you can explicitly opt out. This affects `Interactive` on `DotNetRestoreSettings`, `DotNetReferenceAddSettings`, `DotNetProjectConvertSettings`, `DotNetWorkloadInstallSettings` and `DotNetWorkloadRestoreSettings`, and `CreateManifestIfNeeded` on `DotNetToolInstallSettings`. `null` (default) leaves it to the .NET CLI, `true` / `false` are passed on explicitly, i.e. `--interactive false` ([#5169](https://github.com/cake-build/cake/issues/5169)).
- **Autofac replaced by Microsoft.Extensions.DependencyInjection** in Cake.Tool ([#2835](https://github.com/cake-build/cake/issues/2835)). Modules registering through `ICakeContainerRegistrar` keep working as before.
- **Obsolete members removed** ([#5003](https://github.com/cake-build/cake/issues/5003)) and **Spectre.Console.Cli updated to 0.57.2** ([#5079](https://github.com/cake-build/cake/issues/5079)).
- **Cake.Sdk** — The generated public `Program.ServiceProvider` is gone in favour of the Cake.Common `ServiceProvider` alias, so replace any `Program.ServiceProvider` with `ServiceProvider` or `Context.ServiceProvider` ([generator#203](https://github.com/cake-build/generator/issues/203)). Likewise, the generated `InstallTool` helpers are replaced by the Cake.Common aliases, existing `InstallTool(...)` calls keep working, but `Program.IToolInstaller` references should use `Cake.Core.Tooling.IToolInstaller` ([generator#201](https://github.com/cake-build/generator/issues/201)).

### One container, one host

With Cake.Tool migrated from Autofac to Microsoft.Extensions.DependencyInjection ([#2835](https://github.com/cake-build/cake/issues/2835)), all three runners now share the same DI container, and the `ServiceProvider` alias that Cake.Sdk users already know is now available on `ICakeContext` everywhere.

That means services registered by a module loaded with the `#module` directive can be resolved straight from your script:

```csharp
#module nuget:?package=Cake.MyService.Module&version=1.0.0

Task("MyTask")
    .Does(() =>
{
    ServiceProvider
        .GetRequiredService<IMyService>()
        .DoWork();
});

RunTarget("MyTask");
```

The very same module works with Cake Frosting, where you also get constructor injection into your tasks:

```csharp
return new CakeHost()
    .UseModule<MyServiceModule>()
    .ConfigureServices(services =>
        services.AddSingleton<IOtherService, OtherService>())
    .Run(args);

public sealed class MyTask(IMyService myService) : FrostingTask<FrostingContext>
{
    public override void Run(FrostingContext context)
    {
        myService.DoWork();
        context.ServiceProvider
            .GetRequiredService<IOtherService>()
            .DoWork();
    }
}
```

Cake.Sdk now also runs on the same `BuildScriptHost` as Cake .NET Tool ([generator#208](https://github.com/cake-build/generator/issues/208)), so settings and behavior are identical regardless of runner. On the topic of consistency, Cake Frosting no longer exits with `-1` for any kind of error; it now returns the `CakeException.ExitCode` (`1` by default), just like the other runners ([#3830](https://github.com/cake-build/cake/issues/3830), [generator#207](https://github.com/cake-build/generator/issues/207)).

### Unified dependency graph by default

In Cake 6.2.0 we introduced an opt-in unified dependency graph when running multiple targets, so dependencies shared between targets only execute once. In Cake 7.0.0 this is now the default ([#5060](https://github.com/cake-build/cake/issues/5060)).

```bash
dotnet cake --target=Test --target=Pack
```

Above, a shared `Build` dependency will now execute once, not once per target. If you rely on the previous behavior, you can opt out via argument

```bash
dotnet cake --target=Test --target=Pack --Settings_UnifiedDependencyGraphForMultipleTargets=false
```

or via `cake.config`

```ini
[Settings]
UnifiedDependencyGraphForMultipleTargets=false
```

### Tools on demand & DSL improvements

`#tool` directives install tools up front, before your build runs. With the new `InstallTool` / `InstallTools` aliases ([#2471](https://github.com/cake-build/cake/issues/2471)) you can install tools from within a task, only when that task actually executes. This works with all runners.

```csharp
Task("GitVersion")
    .Does(() =>
{
    InstallTool("dotnet:?package=GitVersion.Tool&version=6.8.2");
    // ...
});
```

The DSL also received a few quality of life improvements:

```csharp
var unit = Task("Unit");
var integration = Task("Integration");

Task("Test")
    // Depend on multiple tasks, by builder or by name (#1462)
    .IsDependentOn([unit, integration])
    // Async DoesForEach, also supports IAsyncEnumerable (#5129)
    .DoesForEach(
        GetFiles("./artifacts/*.trx"),
        async trx =>
        {
            // IFile content extensions aligned with System.IO.File (#5081)
            var xml = await Context.FileSystem
                                .GetFile(trx)
                                .ReadAllTextAsync();

            Information($"{trx.GetFilename()}: {xml.Length} chars");
        });
```

- `IsDependentOn` and `IsDependeeOf` accept multiple task names or task builders ([#1462](https://github.com/cake-build/cake/issues/1462)).
- `DoesForEach` has async overloads, including `IAsyncEnumerable<T>` ([#5129](https://github.com/cake-build/cake/issues/5129)).
- `IFile` has content read / write extensions mirroring `System.IO.File`, i.e. `ReadAllText`, `ReadAllLines`, `WriteAllText`, `AppendAllLines`, and their async counterparts ([#5081](https://github.com/cake-build/cake/issues/5081)).
- `GetFileSystemInfos` lets you glob both files and directories in one go ([#4660](https://github.com/cake-build/cake/issues/4660)).

### New aliases

Cake 7.0.0 comes with a bunch of new aliases:

```csharp
// Create and extract tar archives (#5087)
Tar("./publish", "publish.tar.gz", new TarSettings {
    Compression = TarCompression.GZip
});
Untar("publish.tar.gz", "./publish");

// Update vulnerable packages (#5089)
DotNetUpdatePackage(new DotNetPackageUpdateSettings {
    Project = "./src/App.csproj",
    Vulnerable = true
});

// Migrate .sln to .slnx (#5105)
DotNetSlnMigrate("./src/HelloWorldApp.sln");

// Convert a file-based app to a project (#5107)
DotNetProjectConvert("./scripts/tool.cs");

// Run C# code via dotnet run - (#5127)
DotNetRunCode("""
    Console.WriteLine("Hello from dotnet run -");
    """);
```

Also new are `DotNetDownloadPackage` ([#5103](https://github.com/cake-build/cake/issues/5103)), `DotNetNuGetWhy` ([#5109](https://github.com/cake-build/cake/issues/5109)) and `DotNetNuGetLocalsList` / `DotNetNuGetLocalsClear` ([#5112](https://github.com/cake-build/cake/issues/5112)), together with new .NET 11 settings for `DotNetRun` ([#5115](https://github.com/cake-build/cake/issues/5115)), Microsoft Testing Platform settings for `DotNetTest` ([#5119](https://github.com/cake-build/cake/issues/5119)) and `Framework` for `DotNetFormat` ([#5117](https://github.com/cake-build/cake/issues/5117)).

### Container publishing

`DotNetPublish` now supports publishing container images ([#5159](https://github.com/cake-build/cake/issues/5159), [#5173](https://github.com/cake-build/cake/issues/5173)), either through the new `Container` settings or the convenience extension methods:

```csharp
// Push to a container registry
DotNetPublish("./src/App/App.csproj", new DotNetPublishSettings()
    .WithContainerRegistry("ghcr.io", "devlead/app", "latest"));

// Load into local Docker, Podman or WSL container engine
DotNetPublish("./src/App/App.csproj", new DotNetPublishSettings()
    .WithContainerLocalRegistry(DotNetContainerLocalRegistry.Podman, "app")
    .WithContainerBaseImage("mcr.microsoft.com/dotnet/runtime:11.0"));

// Save as a tarball
DotNetPublish("./src/App/App.csproj", new DotNetPublishSettings()
    .WithContainerArchive("./artifacts/app.tar.gz"));
```

And as Cake.Sdk builds are regular .NET apps, you can publish your Cake build itself as a container, ready to run in any CI or container environment:

```bash
dotnet publish cake.cs \
  -t:PublishContainer \
  -p:ContainerBaseImage='mcr.microsoft.com/dotnet/sdk:11.0-resolute-aot' \
  -p:ContainerUser=root \
  -p:ContainerRepository=cake-sdk \
  -p:LocalRegistry=Docker
```

### .NET 11 process APIs

When Cake runs on .NET 11, `ProcessSettings` can opt in to the new .NET 11 process APIs on a per process basis ([#5085](https://github.com/cake-build/cake/issues/5085)), i.e. `KillOnParentExit`, `StartDetached`, `RestrictInheritedHandles`, `DiscardStandardOutput` and `DiscardStandardError`, and there's a new `StartProcessAndForget` alias returning the process id.

```csharp
var dotnet = Context.Tools.Resolve("dotnet.exe")
             ?? Context.Tools.Resolve("dotnet");

var processId = StartProcessAndForget(dotnet, "--version");
Information("Process ID: {0}", processId);

var exitCode = StartProcess(
    dotnet,
    new ProcessSettings {
        Arguments = "--version",
        KillOnParentExit = true,
        RestrictInheritedHandles = true,
        DiscardStandardOutput = true,
        DiscardStandardError = true
    });
```

Regardless of .NET version, you can now also pass standard input to a process ([#5125](https://github.com/cake-build/cake/issues/5125)), as a string or bytes:

```csharp
var exitCode = StartProcess(
    dotnet,
    new ProcessSettings {
        Arguments = "run -",
        StandardInput = """
            Console.Write("Hello from stdin");
            """
    });
```

### GitHub Actions to Azure without secrets

Building on the `NuGetLogin` trusted publishing support from Cake 6.3.0, Cake 7.0.0 adds `AzureLogin` ([#5070](https://github.com/cake-build/cake/issues/5070)), which exchanges a GitHub Actions OIDC token for an Azure access token. No Azure CLI and no client secret needed:

```csharp
Task("Deploy")
    .Does(async () =>
{
    var accessToken = await GitHubActions.Commands.AzureLogin(
        EnvironmentVariable("AZURE_TENANT_ID"),
        EnvironmentVariable("AZURE_CLIENT_ID"));

    // ...deploy using Azure SDK / tools
});
```

If you're using Azure.Identity, `AzurePrepareWorkloadIdentity` writes a federated token file that `WorkloadIdentityCredential` / `DefaultAzureCredential` picks up:

```csharp
var workload = await GitHubActions.Commands.AzurePrepareWorkloadIdentity(
    EnvironmentVariable("AZURE_TENANT_ID"),
    EnvironmentVariable("AZURE_CLIENT_ID"));

DotNetRun("./src/Deploy", new DotNetRunSettings {
    EnvironmentVariables = {
        ["AZURE_TENANT_ID"] = workload.TenantId,
        ["AZURE_CLIENT_ID"] = workload.ClientId,
        ["AZURE_FEDERATED_TOKEN_FILE"] = workload.FederatedTokenFile.FullPath
    }
});
```

Your workflow needs the `id-token: write` permission for the token request to succeed.

### Cake.Template cakeci template

Cake.Template has a new `cakeci` template ([generator#255](https://github.com/cake-build/generator/issues/255)), which scaffolds a minimal CI pipeline running your Cake file-based build:

```bash
dotnet new install Cake.Template

dotnet new cakeci --Provider github
dotnet new cakeci --Provider github --OS matrix
dotnet new cakeci --Provider azuredevops
dotnet new cakeci --Provider gitlab --Framework net10.0
```

Supported providers are `github`, `azuredevops`, `bitbucket`, `gitlab`, `appveyor`, `woodpecker`, `rwx` and `bitrise`.

### Addin recommended Cake version set to 7.0.0

We've now set the recommended version of [Cake.Core](https://www.nuget.org/packages/Cake.Core) for addins to target to 7.0.0 ([#5001](https://github.com/cake-build/cake/issues/5001)).

This won't break the build, but you might see warnings like the one below when addins or modules are loaded.

```bash
The assembly 'Cake.Addin, Version=6.0.0.0, Culture=neutral, PublicKeyToken=null'
is referencing an older version of Cake.Core (6.0.0).
For best compatibility it should target Cake.Core version 7.0.0.
```

The recommended target framework monikers for addins are now:

- `net11.0`
- `net10.0`

### ...and more

This release also includes a lot of smaller improvements and fixes: interpolated strings now correctly bind to the `FormattableString` log overloads ([#5155](https://github.com/cake-build/cake/issues/5155), [generator#258](https://github.com/cake-build/generator/issues/258)), using declarations on the first line are no longer hoisted as using alias directives ([#5157](https://github.com/cake-build/cake/issues/5157)), `GetSpecialPath` maps correctly on Unix ([#5095](https://github.com/cake-build/cake/issues/5095)), legacy .NET Framework / CoreCLR host code has been removed and internals modernized with frozen collections, `GeneratedRegex` and System.Text.Json, and the API docs now include Cake DSL examples ([#5024](https://github.com/cake-build/cake/issues/5024), [#5026](https://github.com/cake-build/cake/issues/5026), [#5028](https://github.com/cake-build/cake/issues/5028), [#5030](https://github.com/cake-build/cake/issues/5030)).
